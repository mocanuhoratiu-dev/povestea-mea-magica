## Manual visual review

Pro keeps hairstyle, outfit, clip, lantern and general facial identity between the two scenes. It largely reuses the first background/camera angle despite a request for a new angle. Style reads as a polished painted illustration, not necessarily the site's final cinematic direction. The lantern hand merits closer checking; Pro QC also flagged this.

Flash-Lite accepts a reference generated by a different model. It keeps the recognizable outfit and hair, changes the bench/background more noticeably and shifts facial proportions somewhat. Both 1K outputs are usable concept previews; they do not establish 2K print suitability or reliable identity across an entire album.

## Integration prerequisites

1. Use per-model capabilities and generation settings: resolution, modalities, thinking and output-token allowance.
2. Album text modelCandidates currently slices to two total entries. Simply adding two backups to an environment variable would not enable both behind the primary.
3. Image model count defaults to two total entries too; a three-model chain needs an explicit supported limit and corresponding call/cost budget.
4. Preserve reference images when switching image model, then check identity and style consistency. Do not bypass safety rejection with fallback routing.
5. Keep QC fail-closed. Add actual fallback routing; QC currently has one configured model rather than a model chain.
6. Respect an overall deadline: the 27-31 s image timings are individual samples, not p95 or a capacity guarantee. A primary call consuming its entire timeout leaves less time for backups.
7. Test with runtime service-account credentials and the real SDK/router, using primary-failure injection, before deployment.
8. Test actual product schemas, all 13 story scenes, both kit schemas, long context, photographic personalization with consent, false-positive QC controls and multiple consecutive generations.
